# 湖沼の基図表示

出典：[国土数値情報（湖沼データ）・国土交通省](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-W09-v2_2.html)。2005年9月1日時点、W09-05_GML.zip、556地物。2026年11月20日取得。

湖・貯水池の面形状をMeteoScopeがGeoJSONと表示用ベクトルタイルへ加工。原典は国土地理院の数値地図25000等。島を表す穴と複数ポリゴンを保持し、GeoJSONへの変換では座標を簡略化しない。JGD2000の経度・緯度を用いた背景図で、測量精度を保証しない。

## 利用条件と限界

このデータの許諾条件は**商用可**。[旧利用約款準拠版の利用規約](https://nlftp.mlit.go.jp/ksj/other/agreement_02.html)に従い出典・加工者と利用条件を継承する。元データの権利は各権利者に帰属し、アプリのコードライセンスを湖沼データへ適用するものではない。

整備年の古い背景資料であり、全ての池や現在の湖岸・ダム湖を網羅しない。原典の時間的・空間的誤差や欠落を含み、測量、航行、浸水範囲や避難先の判定には使用しない。アプリの設定内「出典・データについて」にもこの制約と規約を表示する。

## 生成と描画

`npm run data:build:lakes -- path/to/W09-05-g_Lake.shp` で同じZIP内のSHP/DBFから `public/data/japan-lakes.geojson` とメタデータを生成する。既存のshapefile依存を使い、新しい実行時依存はない。

続いて `npm run data:build:base-map-tiles` を実行。既存の市区町村・都道府県と同じタイルに `lakes` レイヤーを含める。既存のタイル化精度・量子化を使い、湖沼入力のハッシュもタイル版へ含める。公開版は湖のための追加ソース・追加リクエストを必要としない。GeoJSONモードでは同じ元データを独立したGeoJSONソースで読み込む。

湖面は市区町村の基図の塗りと地形の上、注意報・警報・早期注意情報の塗りと行政界の下に描く。湖上も市区町村の区域に従い、陸地と同じfeature-stateで色付け・解除する。湖全体を隣接する一自治体の発表で一括着色するものではない。平常時は明暗テーマの海と同じ色を用い、島は元の陸地を残す。湖名ラベル・湖底地形・水位・リアルタイムの水域変化を追加するものではない。

## 検証

- 元データの島・穴を保持する変換、全国556地物、メタデータのSHA-256をテスト。
- 市区町村タイルのデコード結果を生成元と比較。琵琶湖・洞爺湖・霞ヶ浦・宍道湖が通常タイルに含まれ、既存の修正済み5市町の形状も維持されることを確認。
- 実ブラウザーの共有地図レンダラーで、琵琶湖・洞爺湖、明暗テーマ、地形ON/OFF、湖内の島を確認。架空の注意報→警報→特別警報→解除で湖上の区域にも色と黒斜線が反映されることを確認。PC相当・430px幅、ベクトル・GeoJSON両モードを検証。
- ベクトルモードのタイル数は従来と同じ1428件。全タイル合計は14,069,253→14,979,338バイト（約0.91MB増）。湖専用GeoJSONソースは作成されず、追加リクエストはない。GeoJSON切り戻し時は独立ソースを使用する。

ネイティブiOS実機は未検証。上記はローカルでの検証結果であり、公開環境の動作確認とは区別する。
