## 既存コードの調査

`src/jma/amedas.js` が最新時刻、全国実況JSON、観測点表を取得する。通信・実行中リクエストの共有は `jmaClient.js`、位置情報と自治体判定は `location/currentLocation.js`、要約・観測グラフは `ui/leftPanel.js` にある。要約は現在地から最も近い有効な観測点を選んでいた。

観測点の標高・観測要素・品質情報・観測時刻は表示用ポイントに保持されていなかったため追加した。既存の気温、湿度、風、降水量などの取得経路は共用する。欠測の `null` や空文字を `Number()` で0に変換しないよう修正した。

既存の地形表示は陰影・色別画像で、画素から標高を復元できない。数値を符号化した地理院標高PNGを追加し、既存の地形タイル用メモリ・CacheStorage・実行中リクエスト共有を再利用した。地図移動の先読み対象には標高PNGを加えていない。

リポジトリは現在Web/PWA用。ネイティブiOSプロジェクトはないため、共通Webコードへの反映とiPhone相当幅での表示確認を行う。iPhone実機・Safariでの実証とは区別する。

## データと取得経路

| データ | 経路・確認結果 |
|---|---|
| 観測点 | [気象庁の観測点表](https://www.jma.go.jp/bosai/amedas/const/amedastable.json)。実応答1,286地点。`alt` は数値、`lat`/`lon` は度・分配列、`elems` は文字列。度分を十進度へ変換し、範囲を検査する。 |
| 気温 | 既存の `latest_time.txt` → `/data/map/YYYYMMDDHHmmss.json`。実応答の `temp` は `[値, 品質フラグ]`。品質0、有限値、同一スナップショット時刻のみ利用。地点別時刻がある入力では一致も検査する。観測要素の符号を推測して温度の有無を決めず、有効な温度フィールドの存在を確認する。 |
| 地表標高 | [地理院標高PNG仕様](https://maps.gsi.go.jp/development/demtile.html)の `dem_png`。ズーム14、欠測・失敗時は12を一度だけ試す。DEM10B由来で、低ズームは粗くなる。GPS標高は使用しない。 |
| 水域の判定 | 位置情報の自治体検索で読み込んだ既存の自治体ポリゴンを共用。追加の海岸線APIは使わない。 |

PNGは `x=65536R+256G+B`、`x<8388608` なら `x×0.01m`、それ以上は `(x−16777216)×0.01m`。`128,0,0` と透明画素は欠測。0m・負の標高は有効。ブラウザーの色変換・平滑化を抑えて1画素を読み、bitmapを解放する。

公開されたつくばの例示座標で、ズーム14のPNGは200・32,366バイト、`Access-Control-Allow-Origin: *`。海域のタイルは404・同CORSヘッダーを確認した。実ブラウザーでPNGを復号し23mを得た。[標高取得試験サービス](https://maps.gsi.go.jp/development/elevation_s.html)も200・CORS許可、同例示座標で25.2m・5mレーザ由来を確認したが、試験サービスの継続性と精度資料の違いを考え、実装では使用していない。データセット・解像度が違うため両値の一致は要求していない。

## 補間方式と保護条件

補間エンジンはDOM・通信から独立した `temperatureEstimation.js`。運用値は `temperatureEstimationPolicy.js` に集約した。Haversine距離を既存関数で計算する。

- 半径50km、最大8・最低3地点、距離指数2、固定減率0.0065℃/m。
- 四象限の代表を優先した後、距離順で補充する。観測点の偏りを隠すための気温補正は加えない。
- `T補正=T観測−γ(h現在地−h観測点)`、`w=1/max(d,0.2km)^2` の加重平均。0.1km以内なら観測点の実測値を優先する。
- 品質0以外、欠測、非数値、重複ID、時刻混在、観測から30分超、未来2分超は除外する。温度は−90～60℃の範囲を確認する。
- 既知の陸地点間を約3km間隔で検査し、水域を挟む地点を補間から外す。海岸などで判定不能なら低信頼性にする。小さな海峡・湖沼・複雑な海岸を完全には判別できない。
- 標高差1,200mを超える観測点は標高補正に使わない。観測点の標高範囲から300m超の外挿、標高中間値との差600m超、補正後標準偏差4℃超などは推定を控える。
- 最大方位空白が180°超なら観測点の凸包外。300°超かつ最寄り15km超は推定を控える。

上記閾値は保守的な運用制限であり、誤差を保証する検定結果ではない。山の稜線、盆地、都市・海陸風・前線を直接モデル化する検証済み資料はない。経験則による追加補正は行っていない。

動的候補は距離重み付き回帰 `T=a+bH` と `T=a+bX+cY+dH`。水平勾配と高度の寄与を分けた候補も実装した。負の気温減率（逆転）を許容する。地点数、高度幅150m、行列の安定性、R²、外れ値、減率絶対値0.015℃/m以下を確認する。内側LOOで固定減率よりMAEが0.15℃以上かつ10%以上改善し、最大誤差が悪化しすぎず、減率の標準偏差が0.003℃/m以下の場合だけ候補として採用する。

ただし今回の実測比較では動的候補の一般的優位を確認できなかった。`dynamicEnabled=false` とし、通常表示には固定減率を使う。動的方式は検証用の明示指定でのみ実行できる。

## フォールバックと信頼性

実運用は、固定減率付きIDW → 標高がない場合の通常IDW → 補間困難時の最寄り観測点実測値 → 取得不可。将来、独立検証で動的方式の採用が承認された場合は、動的方式 → 固定方式となる。

実測値へのフォールバックも新しい品質0の観測に限定し、100kmを超える地点は使わない。欠測を0℃に置き換えない。実測値は「推定」と表示しない。

地点数、最寄り・平均距離、最大方位空白、凸包外、標高差、補正後のばらつき、データ年齢、動的回帰の安定性を保持する。15分超の観測、標高補正が大きい条件、水域判定不能なども注意条件となる。内部分類は高・中・低・推定不可。統計的な信頼区間や保証精度として表示しない。

## UIとキャッシュ

設定 → AMeDAS →「現在地の推定気温」。アーリーアクセス限定、初期OFF。アーリーアクセス無効時はスイッチを無効化し、設定値が保存されていても計算・標高取得を開始しない。OFF・権限失効時は実行中の標高取得を中断し、遅れて返る結果を破棄する。

要約の高さを変えず「推定 10.4℃ ⓘ」のように表示する。情報ボタンから、実測値・距離・標高・地点数・日本時間の観測時刻・使用観測点・注意条件・出典を確認できる。ダーク／ライト、日本語／英語、画面内に収まる詳細ポップアップに対応。観測点を選択したグラフは従来どおり実測値。気温以外の補間は行わない。

標高取得中は最寄り実測値を表示し、地図や要約全体の描画を待たせない。0.1℃表示は精度の保証でない旨を明記する。

観測点表は既存の共有キャッシュを7日TTLへ延長し、HTTPキャッシュも再利用する。実況のキャッシュ・更新経路は増やさない。DEMは既存の8MiBメモリ・32MiB/512件ディスク上限を共用する。標高アンカーはメモリ最大8件・成功24時間、100m未満の移動で再利用、失敗は15分抑制。正確なGPS座標をディスクに保存しない。既存タイルキャッシュのキーはタイル番号のみ。

同一の元観測データ配列・観測時刻・位置では再計算しない。表示用の配列再生成をキーにしないことで更新ループを防いだ。地図の拡大縮小は再計算の契機にしない。観測更新や100m以上の移動で再計算し、再描画時には年齢も再確認する。標高の各要求は8秒で中断し、親タイルへの試行は一度だけ。失敗時の無限リトライはない。

## 周辺環境を組み合わせた改善（2026-11-26）

### 採用方式

標高補正付きIDWに、土地利用と地形の類似度を組み合わせた。建物・道路・鉄道の面積割合、森林、農地、内水面、海の割合、メッシュ内標高差、平均傾斜、地点標高とメッシュ平均標高の差を利用する。「市街地なら何℃足す」といった未検証の気温補正は行わない。

土地利用の差 `L` は5区分と残余区分の面積割合のL1距離の半分。地形の差 `R` は、標高差の違い/500m、傾斜の違い/30度、地点とメッシュ平均の相対標高の違い/300mをそれぞれ0〜1に制限した平均。

`similarity = max(0.2, exp(-2 × (L + 0.5 × R)))`

観測点の選択は `distance / similarity^(1/p)` を優先しつつ従来の方位分散を維持し、最終重みを `similarity / distance^p` とする。指数p=2、気温減率0.0065℃/mなど既存の安全条件は維持した。この類似度と尺度は経験的なモデル定数であり、物理的に確定した効果量ではない。動的減率の本採用は引き続き無効。

対象位置・候補観測点すべての環境情報が利用できる場合だけ適用する。1地点でも不足、圏外、通信失敗、破損データ、標高不明の場合は従来の標高補正付きIDWまたは通常IDWへ戻す。観測点に一致・地点不足の場合は環境通信を開始せず、実測フォールバックを維持する。観測更新の処理中は同じ場所の有効な推定を保持し、「推定を更新中」と表示する。

### 費用・通信・負荷

全国分の加工済み配信データは176ファイル、計11,266,816バイト（約10.75MiB）、1地域64,016バイト。端末は50km以内の候補と現在地に必要な地域だけ取得する。最大2並列、8秒で中断、失敗は15分保持、地域データはメモリLRU最大12件・24時間。HTTPキャッシュはバージョン別1年immutableとし、同じ地域の同時要求をまとめる。OFF・EA無効時は取得しない。

追加の動的API・D1・DO・定期実行・サーバー計算はない。Pagesの静的配信だけを増やす構成で、Cloudflareの動的リクエストを追加しない。対象メッシュ番号は配信元に送るが、正確な現在地の緯度・経度は送信しない。既存のGSI標高・JMA観測キャッシュ、水域判定を再利用する。実際の端末通信量は地域数とHTTP圧縮に依存する。

### 変更ファイル・確認

`environmentMesh.js` は生成・クライアント・交差検証で共有するスキーマ／復号。`environmentProfile.js` は環境差、`environmentData.js` は通信・キャッシュ、`environmentCoverage.generated.js` は対応地域一覧。既存のエンジン、コントローラー、詳細画面、設定説明、英語表示を拡張した。既存の全画面描画や他の観測項目の推定方式は変更しない。元データの全国取得経路を端末側には追加しない。

追加自動検査は実データ復号、メッシュ境界、欠測と負標高、地域・スキーマ誤り、類似度とフォールバック、同時要求の統合、失敗の抑制、LRU、キャンセル、観測更新中の保持、実測への切替、出典表示を含む。距離計算・時刻・水域判定・HTMLエスケープ・設定スイッチを重複実装していない。iOS PWAも同じWebコードを利用する。ネイティブiOS/Xcodeプロジェクトはこのリポジトリにない。

今後は季節と気象条件を分けた別期間で再検証し、必要なら環境係数を弱める／無効化する。都市・沿岸・山地ごとの改善を保証する表示や、追加の気温加算は採用しない。GitHub反映・CI・公開配信はコミット／デプロイ指示を受けてから実行する。

改善後の確認：全181スイート成功、失敗0。プロダクションビルド成功（261モジュール、既存の700kB超チャンク警告は残る）。CRLFを含む既存ファイルの改行を保持し、`git -c core.whitespace=cr-at-eol diff --check` を通過した。176バイナリすべてのヘッダー・サイズ・年度と、351元ZIPのSHA-256記録を検査した。public全体は約6,600ファイルで、個々の新規バイナリは64,016バイト。

### 有効化時の利用規約とトグル表示

一般的な精度の注意書きと独自加工・出典の説明は、設定をOFFからONにする際の利用規約へ移した。「同意してオン」でのみ有効になり、キャンセル・閉じる・EscapeではOFFを維持する。OFFへの切替に確認は不要。設定と推定詳細の「利用規約・出典」から再確認できる。既存の保存済みON設定は維持する。地点ごとの低信頼性や実測へのフォールバックの注意は通常の詳細に残す。

設定値とARIA属性だけでなく、既存の`settings-switch`の`is-enabled`も同期し、ON時には青色・つまみ右寄せ、OFF時には灰色・左寄せにする。他の設定スイッチと同じCSSを再利用する。ブラウザーの独立したメモリ内設定で、実際の設定モジュールのON描画・OFF操作・利用規約表示・取消を検証した。利用規約の同意による状態更新と重複操作・権限失効は自動テストで検証する。
