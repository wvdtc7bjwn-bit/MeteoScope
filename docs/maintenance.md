# MeteoScopeの保守ガイド

## 実行と確認

```sh
npm ci
npm test
npm run build
```

Windows PowerShellでは必要に応じて`npm.cmd`を使います。
`npm test`は`Tests/`直下の`*Tests.mjs`を名前順に別プロセスで実行します。
途中の失敗で打ち切らず、最後に成功・失敗したスイート数を出力します。
各スイートの上限は120秒です。ベンチマーク、データ更新、デプロイは実行しません。
新しい回帰テストもこの名前で追加すれば全体テストに含まれます。
GitHub PagesのCIも同じコマンドを使用します。個別の`test:*`は開発中の絞り込み用です。

テスト成功は実機での完全な動作保証ではありません。変更した画面はブラウザで確認し、
画面サイズ、ライト／ダーク、位置情報拒否、通信断からの復帰も変更範囲に応じて確認します。
ローカル検証・CI・公開環境での検証は分けて報告します。

## 変更時に維持する契約

- 地震情報、EEW、過去検索、震央分布は独立した表示状態として扱う。
  続報・取消・期限切れ・複数イベントと、遅れて完了した取得をテストする。
- カメラ移動とデータ更新を分ける。続報・再接続で利用者の操作を奪わない。
- 設定の保存キー、初期値、旧形式、ストレージ拒否時のフォールバックは互換性の対象。
  設定を移動するだけの変更でキーを変えたり、保存内容を消したりしない。
- 認証・先行機能の制御は表示の非表示だけで置き換えない。
- 時刻、欠損数値、震度階級、座標の扱いは配信元ごとの仕様を確認する。
  似た処理でも意味が異なるものを一律に共通化しない。
- CSSは後方のルールが優先される。機械的な並べ替え・重複削除はしない。
  分割する場合も適用順序、相対URL、レスポンシブ条件を維持して検証する。
- 地図データや走時表など生成物の大きさだけを理由に、精度を落としたり再生成しない。

## HTML文字列

`src/utils/html.js`を使用します。HTML本文と引用符で囲んだ属性値用です。
URLの許可判定、CSS、JavaScript文字列のエスケープは別の処理が必要です。

| 関数 | null / undefined | アポストロフィ |
| --- | --- | --- |
| `escapeHtml` | 空文字 | `&#39;` |
| `escapeHtmlString` | 文字列化 | `&#39;` |
| `escapeHtmlPadded` | 空文字 | `&#039;` |
| `escapeHtmlStringPadded` | 文字列化 | `&#039;` |

変種は既存の出力を変えないために残しています。新規コードは原則`escapeHtml`を使います。
外部文字列をそのままHTMLとして挿入しないでください。

## 今回の整理の境界

設定保存をアプリ制御から分離し、地図・パネル・モーダル・管理画面・XML表示で
重複していたHTML変換を共有しました。通信頻度、API、サーバー資源、認証、
UIのDOM構造、CSSの適用順序、地図の描画アルゴリズムは変更していません。

`app.js`、`leftPanel.js`、`weatherMap.js`、`style.css`はまだ大きなファイルです。
今後は機能単位で依存関係とテストを用意して分離し、一括で書き換えない方針です。
ソース文字列の配置だけを検証している既存テストは、処理を移動する際に参照先を更新し、
併せて実際の入力・出力を確認するテストを追加してください。

コミット・本番公開は利用者の指示がある場合に実施します。
