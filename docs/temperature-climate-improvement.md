# 現在地の推定気温：地域の平年差による改善

2026-11-27。数値予報を入力に追加せず、アーリーアクセス内の既存の推定気温に組み込んだ。推定気温そのものは初期OFFのまま。検証段階ではコミット・GitHub反映・デプロイせず、気温の表示元切替を実装した後にユーザーのリリース指示を受けた。

## 実装した方式

従来の気温補間を維持し、海域率0.1以上の沿岸代理条件、または採用した観測点の方位分布に180度を超える空白がある場所に限り、地域の平年の気温差から追加の補正を求める。前者は精密な沿岸分類ではなく、既存の約1km土地利用メッシュの代理指標。

背景場には、その日の最高・最低気温の1991～2020年平年値の中点を使う。これは日平均平年値でも時刻別平年値でもない。対象地点の平年値を既知とする前回の試算と異なり、任意の緯度・経度・地表標高・海域率・市街地率から背景値を計算できる。

背景モデルは半径150km・最大32地点・最低8地点の正常な歴史的平年値から作る。海面更正した平年値 `B_i = (最高平年値_i + 最低平年値_i)/2 + γ h_i` に対し、東西・南北距離、標高、海域率、市街地率を説明変数とする局所ridge回帰を行う。水平距離は100km、標高は500mで規格化し、切片以外に0.01の正則化を加える。回帰の距離重みは `1/max(d,10km)^2`。

現在地の背景予測 `B_target` と、従来の補間で採用した観測点の背景値の加重平均の差を求め、

```
Δ = clamp(0.5 × (B_target − Σ w_i B_i), −2℃, +2℃)
T_new = T_existing + Δ
```

とする。固定減率の補正を二重に加えていない。減率は既存の0.0065℃/m、実況に使う地点の選定・寄与率・欠測判定・外挿制限・フォールバックは変更していない。実況値の水平勾配の追加や、風による未採用の重み変更は有効化しない。

観測点に実質的に一致する場合、標高がない場合、周囲が十分に対象を囲む内陸、近隣実測へのフォールバック時、背景用の品質の良い地点が足りない場合などは従来方式を使う。既存の実況に採用した地点の平年値が一つでもない場合も追加補正をしない。線形代数の解法は既存の減率回帰と共通化し、不安定な行列では補正しない。

背景補正によって信頼性を上げることはしない。従来の内部分類が高の場合は中に抑え、補正量が上限に達した場合は低にし、詳細に注意条件を表示する。分類は統計的な信頼区間ではない。

## データ品質の修正

気象庁の元CSVでは、値が0であってもRMKが0なら「統計値なし」であり、RMK8が正常値である。従来の変換スクリプトは値列だけを読み、統計値なしを0℃として格納していた。

- CSV変換を共通のパーサーへ分離し、RMK8かつ有限値だけを採用する。
- 正常な0℃と負の気温は残す。空欄、null、統計値なし、品質不良は0℃に変換しない。
- 日別ファイルの実際の月日だけを読み、平年値のない地点を生成データから除く。
- 公開元ZIPから919地点分を再生成した。既存のグラフもこの修正済みデータを共用する。
- データURLを`v=2020-6-quality`へ更新し、古い静的キャッシュと区別する。ルート配信とサブディレクトリ配信の両方でアセットのベースパスを使う。

新しい905地点分の小さなメタデータは、既存のAMeDAS観測点表と土地利用データから作る。観測点名やユーザーの位置をモデルに埋め込まず、公開観測点ID・座標・標高・海域率・市街地率だけを格納した。日別平年値を別途複製していない。

## 検証の分離

1. 過去に使った12時刻のうち、固定した地域fold0以外の8,086補間成立ケースで、背景の種類、ridge、補正強度の8候補を比較した。対象地点の現在の観測値に加え、その地点の歴史的平年値も背景の学習側から除外した。
2. 当初の全域適用候補は、別の5時刻では平均・最大誤差が減ったが、係数選択に使っていない地域fold0の95%点が2.5244→2.5283℃とわずかに悪化したため、そのまま採用しなかった。この5時刻を次の候補の独立評価結果と呼んでいない。
3. 元の調整用ケースで4種類の適用条件を比較し、沿岸代理条件または観測点分布外という条件を選択した。
4. 適用条件と係数を固定してから、上記5時刻と異なる8時刻を追加取得し、最終評価した。

最終評価時刻は2026-11-25の00・06・12・18時と、11-26の02・08・14・18時（JST）。新たな時刻ではあるが、すべて同じ晩秋2日間であり、近接時刻の時間相関もある。多季節・長期間の独立評価とは扱わない。

地域fold0は約20～40kmの固定した緯度経度ブロックに基づく対象地点の予約集合で、係数・適用条件の選択に使わなかった。ただし、実運用で利用できる周辺の実況・歴史的平年値まで地域丸ごと消した評価ではない。LOOでは対象地点自身の現在観測と歴史的平年値を必ず取り除いた。

検証は既存の前景補間が成立した同じ6,276ケースで比較している。値を非表示にして誤差を減らしたわけではない。全7,324ケース中、近隣実測へのフォールバックと取得不可は別集計。追加補正は1,333ケースに適用した。

## 最終評価結果

単位は℃。集計の表示桁は、推定値自体の精度を保証しない。

| 指標 | 従来 | 改善後 |
|---|---:|---:|
| MAE | 0.9310 | 0.9119 |
| RMSE | 1.3055 | 1.2775 |
| Bias | −0.0867 | −0.0473 |
| 絶対誤差95%点 | 2.7523 | 2.6969 |
| 最大絶対誤差 | 8.1399 | 7.9328 |
| 絶対誤差3℃以上 | 238件 | 225件 |

沿岸代理分類の472ケースではMAE1.2685→1.1387℃、最大誤差6.8320→6.2272℃。標高800m以上の144ケースは、この最終評価では適用条件に該当する補正がなく、結果を維持した。観測点の分布範囲外1,333ケースではMAE1.1764→1.0936℃、最大誤差8.1399→7.9328℃。

予約した地域fold0の872ケースも、MAE0.9092→0.8911℃、RMSE1.3078→1.2788℃、95%点2.6545→2.6221℃。最大誤差は7.3669℃のままで、改善していない。

**全地点の改善ではない。** 個別ケースでは852件が改善、481件が悪化し、1℃超悪化したケースも1件あった。11-25の18時の最大誤差は約0.047℃増え、95%点も約0.008℃増えた。全8時刻でMAEとRMSEは減ったが、一時刻・一地点も悪化しないという保証はない。全体の最大誤差も約8℃残り、局地的な冷気滞留などを解決したとはいえない。

実装したJavaScriptと、候補の検討に用いた独立したNumPy実装を全7,324ケースで照合し、最大差は約4.8×10^-13℃だった。日付、対象の観測値と平年値の除外、背景の欠測時の無変更を確認した。

## 気象庁の分布との再照合

前回取得した11-26の19・20・21時の2,349ケースで、今回の実装を気象庁公開画像の1℃幅カテゴリの中点と再照合した。

| 気象庁区間中点との差 | 従来 | 今回の実装 |
|---|---:|---:|
| 平均絶対差 | 1.1437℃ | 1.1207℃ |
| RMSE | 1.5642℃ | 1.5298℃ |
| 絶対差95%点 | 3.3353℃ | 3.2916℃ |
| 最大絶対差 | 6.9321℃ | 6.9321℃ |

前回の「対象地点の平年値が既知」の方式とは異なる。今回は対象の歴史的平年値も除いた。この3時刻は開発に使った期間であり、上記の最終評価8時刻と同列の独立した証拠にはしない。気象庁の分布自体にも対象のAMeDASやLFMなどが入るため、真値・独立観測・数値予報なしの製品とは扱わない。MeteoScopeの入力に気象庁の推計値やLFMを追加していない。

## 通信・計算・UI

- 既存の推定気温を先に表示し、追加の静的データを読み終えた後に補正する。データ取得中に地図や要約を止めない。
- グラフと背景補正で平年値の取得Promiseとキャッシュを共用する。メタデータは内容ハッシュ付きファイル名、成功結果は共用、失敗は15分間抑制する。日付ごとの展開キャッシュは最大2日。
- 追加のメタデータは非圧縮46,239バイト、ローカルgzipで12,515バイト。共用の日別平年値は非圧縮2,580,070バイト、ローカルgzipで378,936バイト。まだ平年値を取得していない端末ではこれも初回に取得する。CDN上の実転送量は今回測定していない。
- 位置・観測値が更新されたときだけ計算する。地図移動や再描画のたびには計算しない。ローカルWindows/Nodeの400回計測は中央値約0.18ms、95%点約0.46ms。スマートフォン実機の性能値ではない。
- 正確な現在地を新しいサーバーへ送信しない。背景用通信は固定の静的アセットのみ。新しいWorker、D1、DO、定期実行、有料サービスは追加していない。Cloudflare無料枠全体の将来利用量を保証するものではない。
- OFF、移動、データ更新後の遅延応答や、古くなった実況へ補正結果を適用しない。途中で背景データが読めなくても従来の有効な推定を保つ。
- 要約は従来どおり気温だけ・同じ字体。詳細に平年差補正の説明と補正量を追加する。湿度・風・雨・雪の計算は変更していない。

## 変更した主なファイル

- `src/location/temperatureClimate.js`: 任意地点の背景回帰と限定補正。
- `src/location/temperatureClimateData.js` / `temperatureClimateData.generated.js`: 共用平年値と静的メタデータの読込。
- `src/location/localTemperatureController.js` / `temperatureEstimationPolicy.js`: 非同期適用とアーリーアクセスの既存経路。
- `src/utils/linearSystem.js` / `src/location/temperatureEstimation.js`: 小規模線形方程式の解法を共通化。既存の減率回帰の計算は維持。
- `src/amedasTemperatureNormal.js` / `scripts/lib/amedasTemperatureNormals.mjs` / `scripts/build-amedas-temperature-normal-data.mjs`: 正常な0℃と欠測の区別。
- `scripts/build-temperature-climate-data.mjs`: 公開観測点メタデータの生成。
- `scripts/validate-temperature-climate.mjs`: 本番の補正モジュールによる凍結ケースの再評価。
- `src/ui/localTemperatureView.js` / `public/sw.js`: 詳細説明と静的キャッシュ。
- `Tests/TemperatureClimateTests.mjs` / `Tests/AmedasTemperatureNormalTests.mjs`: 数値、品質、非同期制御、再利用・失敗・取消の回帰検証。

## 確認結果と再現

全187テストスイートが通過し、最終の関連変更後も39テストと平年値テストを再実施した。ルート用と`/MeteoScope/`用のViteビルドも確認。ブラウザーの検証ページで、実際の静的データ読込、補正値、診断の展開、ライト・ダーク、430px幅での横はみ出しなし、数値の12px・900・共通フォントを確認した。検証ページは公開観測データを使うローカルfixtureであり、GPSから地表標高までの全実環境の実証やiPhone/Safari実機検証ではない。

このリポジトリにはネイティブiOSプロジェクトがなく、iOS向けにも共通Web/PWAコードへ反映している。GitHubのCIビルドは、コミット・pushを指示されていないため起動していない。

```
node scripts/build-amedas-temperature-normal-data.mjs --source .cache/temperature-tail-research/normal-source.zip
node scripts/build-temperature-climate-data.mjs --stations .cache/temperature-audit/stations.json
node scripts/validate-temperature-climate.mjs --input .cache/temperature-climate-research/gated-evaluation.json --reference .cache/temperature-climate-research/gated-evaluation-predictions.json --output docs/data/temperature-climate-validation.json
npm test
npm run build
```

入力ケース・比較用NumPy出力はGit対象外のローカルキャッシュにあり、リポジトリだけには生データを同梱していない。取得時刻とURL・SHA256、候補選択の段階は `docs/data/temperature-climate-validation-design.json`、実装とアセットのハッシュ・集計は `docs/data/temperature-climate-validation.json` に記録した。公式のリアルタイムURLの保存期間を過ぎると同じデータを再取得できない場合がある。

## 残る改善点

大きな局地誤差をさらに減らすには、季節と時刻別の背景、盆地の冷気滞留・地形の遮蔽・海岸距離の表現、観測点の移設と歴史的平年値の整合、多季節の別日検証が必要。これらを未検証の固定加減算で代用しない。今回の2日前後の検証だけで一般精度を保証しない。
