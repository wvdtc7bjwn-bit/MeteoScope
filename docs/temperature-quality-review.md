# 推定気温レビュー対応記録

2026-11-26。基準はローカル・GitHub mainが一致した `179550649178dd4a0e84c22ede12496d0ebb2ee6`。開始時の作業ツリーはクリーン。今回の修正はローカルで行い、コミット・push・デプロイ・新しいGitHub CIは実行しない。

## 修正した原因と挙動

1. 選抜前の最寄り距離が、選抜後の外挿抑制・遠距離注意・confidenceを良くしていた。既存の`nearest`は参照実測・フォールバック用として維持し、最終採用点から`nearestUsed`を取得して品質判定に使う。実質一致100m以内の実測優先も維持する。最大寄与率と`N_eff=1/Σ(weight²)`も診断へ追加した。これら新しい寄与率指標だけで値やconfidenceを変更しない。実測は寄与率1・有効数1、取得不可は寄与率不明・有効数0。補間に採用した最寄り距離は実測・取得不可では不明とする。
2. 自治体データの失敗済みPromiseが残り続けていた。共有の再試行処理へ置き換え、進行中・成功結果を共有、失敗は30秒バックオフ、1要求10秒で打ち切る。再取得は後続の呼び出し時のみ。古い要求の遅延失敗が新しい結果を消さない。コントローラーの水域チェックにも同じ処理を使い、観測が同じでも後の分更新で復旧を試せるようにした。
3. 地域情報の失敗がGPS取得失敗と混同されていた。座標取得済みなら`status: found`を維持し、別の`geographyStatus`で地域取得の失敗を示す。時計の天気表示も「地域情報を取得できません」と区別する。警報の取得失敗を空の成功データとして保存しない。
4. GPSの水平位置精度・取得時刻が消えていた。座標と対応する`accuracy`と`positionTimestamp`をメモリ内で保持し、自治体・警報再解決、推定、詳細へ渡す。未知・不正な精度はnull。精度だけの変化では標高・環境を再取得せず、温度も補正しない。水平精度1km超で注意を付ける。これは約1km環境メッシュを扱う際の運用上の目安であり、検証済みの温度誤差・統計的精度ではない。精度改善時は注意を解除して元の観測条件によるconfidenceへ戻す。
5. 低い条件は要約に「参考」を文字で表示し、アクセシブルな名前にも反映する。更新中にも参考表示を保持する。実測・計算中・更新中・取得不可を区別する。一般的な精度説明と出典は従来どおり有効化時の利用規約から確認できる。
6. 再描画で詳細を閉じる処理を変更し、同じ地点の更新は開いたまま内容を更新する。展開したdetails・スクロール・フォーカスを保持し、条件付きの項目が増減しても同じ操作へフォーカスを戻す。要約の差し替えにも追従する。Escape・明示的な閉じる・OFF・タブ切替など結果が消える場合・100m以上の地点移動では閉じる。100m未満のGPSの揺れは既存の補間キャッシュ範囲として扱い、最新の位置メタデータを表示する。

## 通信・無料運用・残る制約

通常成功時は共有とキャッシュを再利用し、追加取得はない。失敗時だけ後続呼び出しで再取得できるようになる。標高・環境キャッシュ、同時要求の統合は維持する。GPSの精度・時刻はメモリと画面だけに使い、今回の修正でサーバー送信・ディスク保存・高精度GPSの常時要求を追加しない。有料API、Workerルート、D1、Durable Objects、定期ジョブは追加しない。Cloudflare全体の将来の利用量を保証するものではない。

距離、時刻、HTMLエスケープ、標高、環境復号を既存実装で共有した。市区町村検索も同じ関数を再利用し、自治体と水域コンテキストの再取得処理を共通化した。モデル係数・データの生成し直し・解像度低下は行っていない。

検証は過去に開発でも使った秋の短期間であり、独立した季節別検証ではない。観測点表の標高を使うためGPS・DEMの誤差、建物内外の違いは含まない。1kmのGPS注意と有効観測点数は統計的保証ではない。今後は別季節・夜間逆転・沿岸・盆地・山間部の公開観測で品質の変化、フォールバック、位置精度の影響を評価する。地域の通信失敗からの実機での復旧も別途確認が必要。
