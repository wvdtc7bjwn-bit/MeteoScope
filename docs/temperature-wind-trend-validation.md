# 推定気温：風向・風速と朝の気温変化の併用検証

2026-11-27。数値予報は使わず、公開AMeDAS実況だけで風と30・60分前の温度変化を組み合わせて検証した。**採用条件を満たす候補はなく、アプリで新しい補正は有効化していない。** 既存の未コミットの平年差補正を含むアプリの方式を維持した。コミット・push・デプロイは実行していない。

## 結論

併用モデルは未使用時刻の平均誤差を少し減らしたが、誤差の大きい側や地域別・時刻別の悪化が残った。風・昇温を含まない対照モデルとの差は、平均絶対誤差で約0.001℃にとどまった。平均値の改善だけで風・昇温が有効と結論しない。

朝だけ補正する候補も確認したが、朝の95%点と3℃以上の誤差件数が増えた。最大誤差の例である日立の局地的な暖かさは、併用してもほとんど再現できなかった。

## 今回の基準法

作業開始時のソースハッシュを固定した。基準は、標高・環境の類似度を使うIDWに、前回実装した沿岸・観測点分布外の平年差補正を加えた方式。古い風補正は引き続き`weatherEnabled:false`。平年差補正を外した旧方式と比較して改善を大きく見せていない。

## 使用データと品質

- 全国の気象庁AMeDAS地図JSON、既存の観測点表・地形・土地利用・正常な平年値を共用した。
- 気温は品質0、有限値、同じ実況時刻のデータのみ。風も既存の`buildAmedasPoints`による品質判定を共有した。
- 風向は吹いてくる方向。空気の移動方向には逆符号を使い、北付近の風をベクトルで平均する。
- 静穏は方位を北として扱わない。風向コード0かつ風速0.2m/s以下は、測定された風速を残し、方位なしの移動ベクトル0として扱った。説明変数の「弱風割合」は1m/s未満の割合であり、公式の静穏コードの定義とは別。
- 履歴は現在の30分前と60分前。短い履歴は20～40分に限定し、60分前の値を「30分前」として二重に使わない。未来・古すぎる履歴、欠測・風の有効率不足では補正せず、既存の値を維持する。
- 日照時間・気象庁の推計気象分布・数値予報・有料APIは入力に使わない。朝の判定には座標と時刻から求める太陽高度だけを使う。

## 比較した方法

### 1. 風による既存重みの変更

以前の風候補を比較対照にした。現在・過去で地域の風向が持続する場合、異なる風向と環境を持つ観測点の重みを抑える。今回は既存の平年差補正分を維持したまま前景の変化分を加え、基準法から平年差の改善を取り除かない。新しい実験と同じ履歴・データ有効条件で比較したもので、前回の検証数値をそのまま再掲したものではない。

### 2. 空気の移動と観測された昇温を使う補間

過去の各観測点を、その時点で観測された風で現在時刻まで移動させた位置として近接度を計算する。過去の温度に、周辺観測点で実際に観測された地域平均の昇温を加え、現在値の推定と比較する。30分と60分の2候補を作った。

位置の移動は最大15km、重みの変更係数は0.5～2、温度差の原型は±2℃に制限する。これは観測された10分平均風がその後も続く近似であり、実際の空気塊の経路を測ったものではない。最終的な追加補正は全候補とも±1℃に制限した。

### 3. 風・気温変化・環境の組合せによる残差補正

検証対象の気温を周辺から推定した基準値に対し、実測との差を学習する小さなridge回帰を比較した。入力はその地点自身の現在値・過去値を除いた次の特徴量。

- 静的対照：市街地・海域・森林・相対標高の違い、周辺温度のばらつき、朝との相互作用。
- 風：周辺の平均風速、東西・南北成分、風向の整合性と持続、弱風割合、温度と風速の共変動、地形・市街地との相互作用。
- 昇温：30・60分の昇温速度、加速、観測点間の昇温のばらつき、周辺の昇温と地形・土地利用の回帰から推定する対象地点との差。
- 併用：風速と昇温、弱風と昇温、これらと市街地・相対標高などの相互作用。

現在地の風・昇温速度を実測した入力は与えない。回帰の標準化は各訓練foldだけで求め、正規化後の特徴は±5、訓練用の残差は±3℃、追加補正は±1℃に制限した。ridgeは0.1/1、強度は0.5/1、全時間帯/朝のみを比較。風のみ、昇温のみ、併用、静的・太陽位置だけの対照を分け、複雑な回帰を足した効果をすべて風の効果とみなさない。

朝は「太陽高度−6～35度、かつ30分前より上昇中」という実験条件。単純なJSTの時刻帯とは一致しない。

## 調整と評価の分離

調整には、すでに使用済みの25実況時刻と30・60分前の観測を使った。現在・履歴を合わせた70ファイルのうち37は既存キャッシュを再利用した。地域fold0・3の対象地点を係数のfitと候補の順位付けから除外し、残る13,978補間ケースで3つの時間ブロックを交代で隠すOOF比較を行った。診断済みの日立の地域もfold3として予約した。

**各LOOケースでは対象地点の現在の気温・風、過去の気温・風、歴史的平年値をすべて除外した。** 対象の座標・標高・環境は入力するが、実測気温や実測風は特徴にしない。地域foldの予約は係数選択に使う対象の分離であり、実運用で利用可能な近隣の観測を地域ごと消す評価ではない。

比較は48候補。調整用の全条件を満たすものは0だったが、不合格を明記した診断目的で各方式の最良候補と朝専用候補の計11候補を固定し、追加のデータで比較した。係数・適用条件は評価で選び直していない。

固定後に取得した評価時刻は以下の13時刻（JST）。現在時刻もその履歴も、調整用の現在・履歴ファイル集合と重ならない。

- 11月25日：01:20、05:20、07:20、11:20、17:20、23:20
- 11月26日：01:20、05:20、07:20、09:20、13:20、17:20
- 11月27日：00:20

現在・履歴39ファイルを取得。評価対象は11,896地点時刻ケースで、基準法が補間できた同じ10,174ケースで精度を比較した。風・両方の履歴・環境が揃ったのは10,160ケースで、残りも基準値を維持し集計に残す。近隣実測へのフォールバック1,696と取得不可26も消さず、補間とは別扱いにした。朝の集合は3,020ケース、係数選択に使わない予約地域は2,911ケース。

採用条件は、全体のMAE・RMSE低下に加え、全体・朝・沿岸代理・標高800m以上・観測点分布外・予約地域で95%点と最大誤差を増やさず、各時刻のMAE・RMSEも増やさないこと。今回の候補は調整時にも評価時にもこの条件を満たしていない。

## 未使用13時刻の結果

単位は℃。基準は既存の平年差補正を含む。表示桁は推定精度を保証しない。

| 方法 | MAE | RMSE | 絶対誤差95%点 | 最大誤差 |
|---|---:|---:|---:|---:|
| 基準法 | 1.0043 | 1.4153 | 2.9358 | 8.8293 |
| 静的・太陽位置だけの回帰対照 | 0.9907 | 1.3917 | 2.9222 | 8.7786 |
| 風＋静的対照 | 0.9903 | 1.3891 | 2.9320 | 8.7669 |
| 昇温＋静的対照 | 0.9905 | 1.3895 | 2.9185 | 8.7566 |
| 風・昇温の併用（全時間帯） | 0.9898 | 1.3869 | 2.9038 | 8.7619 |
| 風・昇温の併用（朝のみ） | 1.0022 | 1.4110 | 2.9503 | 8.7956 |
| 空気移動30分（朝のみ） | 1.0061 | 1.4180 | 2.9440 | 8.8334 |
| 空気移動60分（朝のみ） | 1.0071 | 1.4192 | 2.9462 | 8.8513 |

併用全時間帯のMAE低下は約0.0145℃だが、風・昇温を使わない対照からの上乗せは約0.0010℃。風の追加効果を約0.0145℃と報告しない。

併用全時間帯では5℃以上の誤差が79→68ケースに減ったが、次の悪化が残る。

- 予約地域の95%点：2.9358→2.9648℃。
- 標高800m以上の最大誤差：4.2557→4.3673℃。
- 11-25の07:20、11:20でMAEとRMSEが増加。11-26の13:20もMAEが増加。
- 個別では5,186ケース改善、4,974ケース悪化し、1℃超悪化が2ケース。

朝専用でも、朝の95%点が3.0755→3.1149℃、朝の3℃以上の誤差が161→168件と悪化した。平均だけでは選べないため、新たな補正の採用は見送った。

前回の最大約8℃の検証とは評価時刻が異なり、今回の基準法の最大8.83℃をアプリ変更による悪化とは扱わない。

## 日立の大きな誤差を補えたか

評価に使った11-26 07:20の日立は、実測9.8℃、基準法0.9707℃、併用全時間帯1.0381℃。誤差は8.8293→8.7619℃で、改善は約0.067℃にとどまった。追加補正は±1℃の上限に達しておらず、上限がこの小さな改善量を決めたわけではない。

予測を固定した後の原因確認では、除外していた日立自身の観測は以下だった。

| 観測時刻 | 気温 | 風速 | 風向 |
|---|---:|---:|---|
| 06:20 | 6.5℃ | 1.6m/s | 西 |
| 06:50 | 8.3℃ | 1.9m/s | 西 |
| 07:20 | 9.8℃ | 1.9m/s | 西 |

対象地点は30分で1.5℃、1時間で3.3℃上がっていた。一方、対象を除いた周辺観測から計算できた上昇は、30分で約0.61℃、1時間で約0.60℃。周辺の平均風速は約0.72m/s、平均風向は北北西付近で、対象地点の西風とも異なった。

つまり、今回の局地差では「現在地の風・昇温を周辺観測から推定する」段階で対象の状況を再現できていない。補間の先に風・昇温の回帰を追加しても、その入力が局地的な西風と昇温を表していない。対象地点自身の温度履歴を入力すれば見かけ上よくなる可能性があるが、観測所のない現在地では持っていない情報であり、今回は不正な精度向上として扱わない。

この観測だけで、実際の暖気の原因がフェーン・混合・海の影響などのどれかを確定したという主張もしない。周辺平均と対象の違いを確認した結果である。全地点で風が役立たないことを証明したわけではなく、今回の方法と期間では安定した上乗せ改善を確認できなかった。

## 確認・再現性

- 候補を固定した時刻と、評価データを取得した時刻を保存し、取得が先行していないことを検査した。
- 各観測ファイルのURL・SHA256を保存し、特徴抽出時に照合した。候補コードが固定後に変わっていないことも検査する。
- 静穏・風向反転・欠測・未来履歴・30分と60分の取り違え・対象の履歴除外・一様な昇温で空間差を捏造しないこと・補正量の上限をテストした。Python側も、評価対象の真値を変更しても予測が変わらないこと、欠測・適用条件・上限を検査した。
- 再実行で全候補の全予測と集計が完全一致した。
- 全188テストスイートとViteビルドが成功。作業前後のメインJS・CSSのSHA256が一致し、今回の研究コードでアプリの動作を変更していないことを確認した。
- 距離、品質、履歴、太陽高度、平年差補正、線形方程式は既存モジュールを共用し、候補を検証用スクリプトに分離した。研究用コード・データはアプリから読み込まない。
- 端末の通常運用に新しい通信・キャッシュ・履歴保持は追加していない。研究で必要な公開データを開発端末へ取得しただけ。新たなCloudflareリソース、課金API、数値予報、正確なユーザー現在地の送信は0。
- iOS向け共通Web/PWAのコードも維持した。iPhone実機やGitHub CIの実行ではない。コミット・push・デプロイは行っていない。

結果・候補・取得情報・ハッシュ：`docs/data/temperature-wind-trend-validation.json`。全ケースと固定した係数・標準化値はGit対象外の`.cache/temperature-wind-trend/`。入力データは同梱せず、公式リアルタイムURLは保存期間を過ぎると再取得できないことがある。

```
node scripts/prepare-temperature-wind-trend.mjs
node scripts/extract-temperature-wind-trend.mjs
python scripts/validate-temperature-wind-trend.py
node scripts/prepare-temperature-wind-trend.mjs --evaluation
node scripts/extract-temperature-wind-trend.mjs --evaluation
python scripts/validate-temperature-wind-trend.py --evaluation
python scripts/validate-temperature-wind-trend.py --self-test
node --test Tests/TemperatureWindTrendTests.mjs Tests/TemperatureWeatherTests.mjs
```

最初の準備コマンドは既存プロトコルの上書きを拒否する。今回の固定済みデータを再確認するときは評価用の抽出・評価コマンドを使い、評価結果を見た後に調整用の係数を上書きして独立検証と呼ばない。

## 制約と次の候補

期間は11-25～11-27未明の約2日間で、季節や別の気象状況の検証ではない。観測点の標高を現在地の地表標高の代わりに使うため、GPS・DEM取得誤差を含むエンドツーエンドの検証ではない。朝の集合は太陽高度による実験定義。地形・沿岸の代理分類や過去の土地利用にも誤差がある。

また、今回は30・60分前の観測がある「起動から十分時間がたった状態」に相当する。通常アプリは新しい風・昇温補正を有効にしておらず、起動直後に現在地の実測風や温度履歴を持つわけでもない。

次に検討するなら、風を足すこと自体より、風向に対する地形の遮蔽・谷や斜面の向き・海岸からの距離などを使い、対象地点と周辺観測の風・昇温の違いを推定できるかが課題。これも別期間で検証してから採否を決める。今回の評価地点や時刻を見て固定の加減算を追加することはしない。
