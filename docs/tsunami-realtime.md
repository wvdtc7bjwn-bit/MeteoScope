# 津波のリアルタイム受信と情報の更新順

津波警報・注意報は、地震情報で使用中のP2P地震情報WebSocket 1本から、コード552も受信します。接続開始・復旧時には最新1件を取得します。履歴の24時間より古い発表だけでは現在の状態を確定せず、XMLの取得が失敗した場合も「警報なし」にはしません。

観測はWolfxの `jma_tsunami.json` のVTSE51・VTSE52と気象庁XMLで補います。Wolfxの警報スナップショットや予想・沿岸推定値で、P2Pの警報や実測値を置き換えません。取得は端末のHTTP通信で、警報・注意報ありでは30秒間隔、通常時は5分間隔です。P2P続報時には即時取得し、同時リクエストはまとめます。新たなWebSocket、Worker、D1書き込みはありません。

警報は全国スナップショットとして公式発表時刻を比較し、観測は製品・関連イベント・発表時刻を分けて管理します。後から届いた古い電文を無視し、同時刻は明示された訂正・発信時刻を優先します。それでも同順位の警報はP2P、観測はXMLを優先します。受信時刻、最大波の観測時刻、MD5の更新だけでは速報を新しく扱いません。訂正による震度・波高の減少や、正式な解除を妨げる最大値固定もしません。

P2Pの `cancelled=true` は警報・注意報の解除です。XMLのInfoType「取消」やWolfx観測報告の `cancelled` は、その報告の取り消しであり、警報の解除とは別に扱います。観測の取消状態も保持し、別経路の古い値が復活しないようにします。イベントIDを確認できる場合は照合し、P2PのようにIDがない場合は解除後の再発表を境に古い観測を混在させません。

通信切断では最後に受信した発表を保持して注記します。Wolfxの `trusted` と `validUntil` を確認し、期限切れ・不明状態から新しい観測を取り込みません。保持する観測にも発表時刻・取得元・更新確認状態を添えます。期限切れは解除に変換しません。地図の準備や古いXMLリクエストが遅れて完了しても、状態の版を照合して新しい表示を保ちます。

2026-11-20の仕様照合で、Wolfxの `expired` 状態だけから「現在の発表なし」と判定しないようにしました。気象庁XMLで独立に未発表を確認できた場合は、その確認結果を使用します。また、後続応答で `trusted=false`・`unknown` などが明示された場合は、以前の信頼期限内でも確認状態を失効させ、保持する観測に更新未確認の注記を付けます。次の定期取得を待たずに `validUntil` 到達時にも再評価し、通信が止まっていても失効を反映します。値や警報の正式な解除・取消とは別に扱います。

検証は `Tests/RealtimeTsunamiTests.mjs` で警報→解除→古い履歴、Wolfx→古いXML→新しい訂正、製品取消、イベント切替、信頼期限、名前と公式海岸線の照合、地図準備との競合、HTTPタイムアウト・停止・再試行を実行します。既存XMLの解析・地図・UIテストも併用します。テスト中の警報・波高は検証用データであり、実際の発表ではありません。
