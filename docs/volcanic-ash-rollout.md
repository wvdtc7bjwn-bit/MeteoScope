# 火山灰予報・警報の移行準備

2026-11-27時点の実装。現在の表示は旧方式を維持する。新しい名称や表示を、サンプルの日時、電文の受信、URLパラメータから自動的に有効化しない。

## 確認した公式資料

- [技術情報684号：火山灰警報等](https://www.data.jma.go.jp/suishin/jyouhou/pdf/684.pdf)
- [技術情報685号：火山灰予報への移行](https://www.data.jma.go.jp/suishin/jyouhou/pdf/685.pdf)
- [2026-11-18 個別コード表](https://xml.kishou.go.jp/jmaxml_20261118_Code.zip) の `VolcanicAshWarning`
- [2026-11-18 公式サンプル](https://xml.kishou.go.jp/jmaxml_20261118_Samples.zip)

名称・運用仕様には変更の可能性がある。開始日は未確定。2027年度中のシステム整備完了と、その後早期の提供開始という予定から、開始日時を推測して設定しない。

## 受信・解析

- VFVO53/54/55の旧形式と新形式を同じ解析経路で受信する。旧形式の71/72/73、新形式の31～37、定時予報の30、噴石の旧75／新40を区別する。
- 新7区分は0.1mm未満、0.1mm以上、1mm以上、1cm以上、3cm以上、10cm以上、30cm以上。**「以上」の累積しきい値**であり、隣接する排他的な深さ区間へ変換しない。
- 元の種別コード、名称、対象地域、予報開始・終了時刻、深さ、範囲を保持する。未知の区分はunknownとし、0や少量に変換しない。
- VFVO70は全国電文として解析し、都道府県と市町村等を別スコープで保持する。発生源は複数保持する。空のEventID/Serialを火山識別子にしない。
- 発表・継続・切替・解除、前回区分、累積火山灰量の記述を保持する。同時刻の訂正は管理部の発表日時等で順序を決める。
- 最新の正常な全国スナップショットで状態を置き換える。古い地域や発生源を混ぜ戻さない。受信失敗、電文の欠落、無効な更新は解除を意味しない。試験・訓練は運用状態へ反映しない。
- 準備データは `fetchVolcanoXmlList().volcanicAsh` に分離する。既存の火山一覧・噴火警戒レベル・地図記号にはVFVO70を混入させない。

## 表示を有効化する前の確認

`src/volcanicAsh.js` の `VOLCANIC_ASH_ROLLOUT` は、予報・警報の開始日時を別々に管理する。両方とも現在は `null`。日時を設定する場合は、タイムゾーンを含むISO 8601を使用する。

1. 気象庁の正式な開始・配信試験のお知らせを確認する。
2. 最新の正式コード表・スキーマ・サンプルを再確認し、今回のサンプルとの差分を検証する。
3. 新予報の7区分、累積ポリゴンの描画順、凡例を検証したうえで `forecastStartsAt` を設定する。現在用意している灰色7段階はMeteoScope側の表示色であり、気象庁公式配色とは称さない。
4. VFVO70の表示経路は今回は受信準備まで。公開時は別途、専用表示・地域コードのGIS照合・自治体別状態の連携を完成させてから `warningStartsAt` を設定する。警報種別を噴火警戒レベルへ変換したり、予報の深さからアプリ独自に警報を発表したりしない。
5. 日付の境界、訂正、全解除、複数火山、未知の区分、試験・訓練、通信障害、ダーク／ライト表示を確認する。

## 通信・保存

既存の短期・長期Atomフィード、XML取得キャッシュ、重複通信抑止を共有する。詳細取得の合計上限32件は維持し、その内最大3件をVFVO70に予約する。VFVO70の取得失敗時は過去キャッシュを新着として扱わず、最後の正常な状態をstaleとして保持する。状態の保持範囲はページの生存期間で、未受信時はunavailableとする。

新しいCloudflareリソース、D1、定期実行、サーバーへの位置送信は追加しない。公式サンプルはテスト専用で、本番のデータやビルドエントリーポイントから参照しない。

## 検証

`node Tests/VolcanicAshCompatibilityTests.mjs` は、公式の旧3電文、新3電文、全国警報3電文を使い、解析・移行ゲート・描画順・状態更新・実際のフィード取得経路を検証する。`node Tests/VolcanoTests.mjs` は既存の火山表示との互換性を検証する。
