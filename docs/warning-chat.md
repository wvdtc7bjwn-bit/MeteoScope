# 防災チャット（Gemma 4、アーリーアクセス）

時計・現在地予報の左にチャットボタンを追加。通常公開版では既存の
MeteoScopeアカウントと管理者のEA許可が必要。画面だけでなくAPIでも認証する。
利用者のCloudflare/Googleアカウントは不要。運営者は既存のCloudflareアカウントを使う。

## 公開前の設定

2026-11-13に対象アカウントのWorkers Freeを管理画面で確認し、
`WARNING_CHAT_ENABLED=true` とバインディング `AI` を設定ファイルへ定義した。
許可済みデプロイで反映する。停止する場合は `false` にする。
未設定・認証失敗・D1障害時は推論しない。
新しいWorker、D1、Durable Object、APIキー、外部ライブラリは追加していない。

1. **既存アカウントがWorkers Freeであることと、同じアカウントの他のAI使用量を確認する。**
   Freeは10,000 Neurons/日を超える処理が失敗する。Paidでは超過分が課金されるため、
   この機能のためにPaidへ変更しない。AI Gatewayの有料クレジットや迂回経路も使用しない。
2. `wrangler.toml` の `[ai] binding = "AI"` で既存PagesにWorkers AIを接続する。
   現行のPages公式資料はWrangler設定ファイルの `ai` をサポートしている。
   このプロジェクトではWranglerファイルを設定の正本として扱い、次回の許可済み
   デプロイで反映する。バインディングの定義・ビルドだけではAI推論を実行しない。
3. 対象環境の `WARNING_CHAT_ENABLED=true`、`WARNING_CHAT_DAILY_LIMIT=none`。
   全体の回数上限は設けない。緊急停止・ローカル検証ではこの変数に0または任意の回数を指定できる。
   AI使用量上限10,000 Neurons/日はサーバーの固定値で、ブラウザや環境変数で増やせない。
4. 公開前に、許可済みアカウントで実際のGemma応答・JSON形式・各言語の意味を確認する。
   未設定のままでは「準備中」を表示する。プレビューと本番で**同じ既存D1**を使用し、
   クォータを共有する。別DBへ向けたりコードの旧版を並行稼働させると上限を共有できない。

対象アカウントのプラン確認と、ローカルでの実モデル検証を実施。
公開時もWorkers Freeを維持し、有料プランへ変更しない。
Viteのローカル専用APIは気象庁資料の確認だけを提供し、AIの認証や上限を迂回しない。

## 費用・上限

- 固定モデル `@cf/google/gemma-4-26b-a4b-it`。1アカウント10回/UTC日。全体は質問回数でなくAI使用量で制御。
- UTC 00:00（日本時間09:00）にリセット。D1 `app_records` の日付別1行を使い、
  条件付きUPSERTとRETURNINGで個人回数とAI予算を**同一SQL文で予約**。
- 推論の前に200 Neuronsを予約。個人の質問回数は、エラー・タイムアウト・回答の検証失敗でも返却しない。
  自動再試行、別モデルへのフォールバック、ブラウザの直接AI接続はない。
- 入力全体のUTF-8は12,288バイト以下、出力は内部推論を含むcompletion上限1,024トークン、n=1。
  Gemma 4の `chat_template_kwargs.enable_thinking=false` を明示する。
  実機能の検証では、既定の思考モードが出力上限を使い切って本文を返さない問題が見つかった。
  上限を増やさず思考モードを無効化し、途切れた回答も表示しない。
  入力をバイト数+1,024のテンプレート余裕として保守的に見積もると、現行価格
  9,091/27,273 Neurons/百万入力/出力トークンで約149 Neurons/回。
  200 Neurons/回を予約し、確認済み使用量＋未確定の予約＋新しい予約が10,000以下の場合だけ受け付ける。
  応答の `usage.neurons` が取得できたら、その予約だけを実測値へ一度だけ置換する。
  小さな応答なら40回を超えて利用できる。使用量不明・失敗・タイムアウトは予約を維持する。
  推論結果が遅れて届いても同じ予約を二重計上・二重解放しない。
  これは**このチャットの使用量と保守的見積もりで、アカウント全体の実測使用量ではない**。
  他機能・他プロジェクトのAI使用、価格変更、日付をまたぐ処理等は別途監視が必要。
  課金を避ける最終防壁はWorkers Free側のハード上限。Paid契約のまま「絶対無料」とは保証しない。
- Cloudflareが無料割当到達エラー3036を返したら、D1に当日停止を保存し、以降のAI呼び出しを止める。
  通常の混雑3040・一般的な429は一日停止と混同しない。日本時間9時の新しい日付で再開する。
  上限付近では次の予約分が確保できず10,000到達前に受付停止する場合がある。
- Workersリクエスト・D1の無料枠もアカウントで共有。回数上限撤廃は無制限の同時利用を保証しない。
  認証済みEA利用者だけが推論できるが、大量のHTTPアクセス自体をこの機能だけで防げない。
- 日付ごとのハッシュ識別子と回数、ランダムな推論予約ID・状態を保存。本文・会話・回答はD1/診断ログへ保存しない。
  同じ日付別レコードに、AIの応答が返した `usage.neurons` の合計と集計できた回数も保存する。
  応答がなく使用量が分からないものを0として補完しない。タイムアウト後に応答が返った場合は
  waitUntilで使用量の記録のみを完了させる（追加推論・再送は行わない）。
  7日より古い専用クォータ行を次回利用時に削除。既存の他のレコードは削除しない。

管理画面の「Cloudflare無料枠」内に、このチャットの設定・停止状態、受付回数、全体の回数上限の有無、
1人の上限、AI応答で確認できたNeurons、未確定件数、保守的な予算見積もり、リセット時刻を表示する。
既存の管理者認証で保護された `/api/admin/quota` から集計値だけ取得し、
個人の識別子・質問・回答は返さない。Analyticsトークン未設定でもこのチャットの集計は読める。
アカウント全体のAI使用量はこの集計では取得できないため、Cloudflareの使用量画面へのリンクを設ける。

## 根拠・鮮度

サーバーが固定の気象庁URLから区域定数、地域の気象警報JSON、時系列JSONを取得。
クライアントが渡した資料・URLは根拠に使わない。既存の警報コード処理と時系列解析を再利用する。
市区町村が取得結果にない場合や取得に失敗した場合を「発表なし」と扱わない。
時系列は発表12時間以内の資料のみ使用し、過去の時間帯を除外。取得できない時は明示する。
現在の警報は古い発表でも継続中の可能性があるため、資料を取り直して確認し、発表の古さだけで解除しない。
気象台全体の見出し文と市区町村の情報は区別。AIへは対象地域以外の記述を適用しないよう指示する。

回答後に資料を再取得し、警報・見出し・時系列の改訂があれば409で回答を破棄。
会話履歴は同じ改訂番号の場合のみ使う。地域・言語の変更、閉じる操作、ログアウト・EA失効で消去。
ユーザーの質問は240文字、履歴は直近4メッセージ。長い履歴から順に除外し、
公式資料そのものが上限を超えた場合は欠落させず推論を停止する。

構造化JSONの形、根拠ID、出典にない数字、HTML/URLを検証。UIはtextContentで表示。
これらの検証は意味の正確さを保証しない。AI由来の説明を明示し、出典・発表/取得時刻を常時確認できる。
解除・安全・避難指示の断定を禁止。指定河川洪水予報、自治体の避難情報、避難経路は初版の対象外。
気象庁の一般的な説明はFAQと時系列の説明ページをもとに要約している。

## 検証

`node Tests/WarningChatTests.mjs`：SQLiteで実際の予約SQLを実行し、並行受付、個人上限/使用量予算、重複使用量報告、旧データ移行、3036での停止と翌日再開、
日付更新、認証/EA制御、古い資料・改訂競合、AI失敗・不正回答の扱いを検証する。
`npm.cmd test` と `npm.cmd run build` も実施。自動テストのAI応答はスタブであり、
実際のGemma品質・Cloudflare推論の成功・スマートフォン実機の検証とは区別する。

### 地震・津波への拡張

- 気象・地震・津波を切り替えて質問する。従来の `/api/warning-chat`、認証と日次クォータを共用し、
  分野ごとに追加枠を作らない。個人上限は1日10回、全分野で同じ10,000 Neuronsの使用量予算を共用する。
- 地震は気象庁 `bosai/quake/data/list.json` と一覧に載る `VXSE51/52/53/5k` のJSONから取得。
  対象地震を最近5件から選べる。震源・規模・深さ・観測最大震度・選択市区町村の震度・
  同じ電文の津波コメントを渡す。発生時刻と発表時刻、観測震度とEEWの予想震度を区別する。
  地震情報中の津波コメントを独立した津波警報の解除と解釈しない。
- 津波は `bosai/tsunami/data/list.json` と同一EventIDの最新 `VTSE41/51/52` JSONを使用する。
  警報・予報と沿岸/沖合の観測値を分け、取消・訂正・有効期限・欠測を扱う。
  期限切れを現在発表中の情報とせず、古い発表を確認しただけで「全国に警報なし」としない。
- 津波予報区は電文に存在するものだけを明示選択する。市区町村から海岸予報区を推測しない。
  1電文・最大8予報区/観測点の概要であることと省略数を明示する。全電文・全観測点の網羅ではない。
- 対象の地震の発生日時と震源地、津波電文の発表日時・期限切れ等を会話欄の上に表示する。
  曖昧な「この地震」「この地域」の質問例を避け、市区町村名と対象を確認して質問できるようにする。
  質問例は「現在発表中の警報・注意報」「最新の地震」「最新の津波情報」と対象を明示する。
  個別イベントを選んだ場合は「選択した地震/津波情報」に切り替え、過去を最新と誤表記しない。
- 全分野で回答生成後に同じ選択条件の公式資料を再取得し、改訂があれば回答を表示しない。
  文量が入力上限を超えた場合は元資料を途中で切らずに停止。モデル・出力上限・回数上限は共通。
- `Tests/SeismicChatTests.mjs` で欠損値、深さ0、取消後の旧報、訓練報、未来時刻、
  予報と観測の区別、期限切れ、対象地域の検証、更新中の回答破棄、出典IDを確認する。
- 2026-11-13、別のローカルD1に全体2回の上限を置き、実モデルへ地震・津波を各1回送信した。
  2回とも認証・EA・予算予約・公式資料の再照合・回答の検証を通過した。地震は観測値と欠損、
  津波は過去電文の発表日時・有効期限と「期限切れは安全を意味しない」という区別を確認した。
  応答の使用量は14.1273および15.1818 Neurons（この2回のみ）。本番・アカウント全体の使用量ではない。
  これは少数例の確認であり、全状況・全言語・災害時の即時性や内容の正しさを保証しない。

### ローカル実モデル検証（2026-11-13）

- Wranglerの通常の認証・AIバインディングを使用し、127.0.0.1の検証環境で既存APIと
  既存UIを実行。本番とは別のローカルD1・テスト用セッション・EA許可を使用した。
  本番DB、公開設定、デプロイは変更していない。
- 検証環境の全体上限を3回に下げ、実モデルへ3回だけ送信。
  初回は思考トークン上限で失敗し、修正後の日本語・英語の2回は本文の解析、
  最新資料の再照合、画面表示まで成功した。修正後の推論時間は約3.2〜3.3秒
  （ネットワーク状況とモデル負荷により変動する）。
- API応答の `usage.neurons` は33.9182、9.4727、13.7818、合計約57.2 Neurons。
  これはテスト3回の値であり、アカウント全体の当日使用量や将来の1回の保証値ではない。
- 実サーバーで未認証401、4回目429を確認し、追加のAI呼び出しがないことも確認した。
- Workersのfetchは `redirect:error` に非対応だったため `manual` に変更し、
  3xxを拒否して外部転送先へ接続しない回帰テストを追加した。
- 通常のViteサーバーは資料閲覧専用のまま。実モデルを使うにはWranglerのAIバインディング、
  ローカルD1の認証・EA設定が必要。ローカルAIもCloudflareへ接続するためオフラインでは使えない。
- UIは会話中心に変更し、地域・言語・出典は上部のメニュー、入力は下部に固定。
  初回送信時にのみプライバシー確認を開き、右上の案内から再確認できる。
  狭い画面・ライト/ダークのブラウザ確認と実機確認は区別する。
- 実回答は少数例のみ。全言語の意味の検証、警報更新と同時の実配信、本番CPU使用量、
  iPhoneなどの実機キーボードを含む動作確認は別途必要。
